# B-4단계 제보 상세·상태 이력 초보자 테스트 가이드

> 대상 브랜치: `feat/report-detail`
> 목표: 코드를 몰라도 `목록 → 상세`, 상세 내용, 처리 이력, 권한 차단을 순서대로 확인한다.

## 1. 테스트 전에 꼭 알아둘 것

- 이 단계는 새 DB migration이나 새 환경변수를 추가하지 않는다.
- 이미 2단계 migration 두 개가 적용된 **개발 DB**를 사용한다.
- `DATABASE_URL`, Discord 비밀 값, 사용자 ID를 화면 캡처나 PR에 붙이지 않는다.
- `TEST_DATABASE_URL`을 사용하는 통합 테스트는 데이터를 만들었다가 지운다. 운영 DB에는 절대 연결하지 않는다.

## 2. 준비물

- Windows PowerShell
- Node.js 22
- pnpm 11.9.0
- 개발용 Supabase PostgreSQL 연결 문자열
- Discord 로그인이 가능한 테스트 계정
- 그 계정이 멤버로 등록된 프로젝트와 `/bug` 제보 1건

프로젝트 폴더는 다음 경로라고 가정한다.

```text
C:\Users\Kang\reproloop
```

## 3. 브랜치와 설치 상태 확인

PowerShell을 열고 아래를 한 줄씩 실행한다.

```powershell
cd C:\Users\Kang\reproloop
git status
git branch --show-current
node --version
pnpm --version
```

성공 기준:

- 브랜치가 `feat/report-detail`이다.
- Node 버전이 `v22...`로 시작한다.
- pnpm 버전이 `11.9.0`이다.

의존성을 아직 설치하지 않았다면 다음을 실행한다.

```powershell
pnpm install --frozen-lockfile
```

pnpm 버전이 달라 `node_modules` 재설치를 묻는다면 바로 동의하지 말고 `pnpm --version`부터 팀에 공유한다.

## 4. 로컬 환경변수 준비

`apps\web\.env.local` 파일이 없다면 만든 뒤 다음 항목에 개발용 값을 넣는다.

```dotenv
APP_URL=http://localhost:3000
DATABASE_URL=개발용_PostgreSQL_연결문자열
AUTH_SECRET=충분히_긴_임의_문자열
AUTH_DISCORD_ID=Discord_Application_ID
AUTH_DISCORD_SECRET=Discord_Application_Secret
AUTH_TRUST_HOST=true
```

주의:

- 값 양쪽에 `<`와 `>`를 그대로 넣지 않는다.
- `.env.local`은 Git에 커밋하지 않는다.
- Supabase 대시보드의 운영 DB가 아니라 팀이 정한 개발 DB인지 다시 확인한다.

## 5. 가장 안전한 자동 테스트

프로젝트 루트에서 실행한다.

```powershell
pnpm --filter @reproloop/shared test
pnpm --filter @reproloop/web typecheck
pnpm --filter @reproloop/web test -- report-detail.test.ts
```

성공 기준:

- 명령마다 마지막에 실패가 `0`으로 나온다.
- `report-detail.test.ts`의 인증 없음, 권한 없음, 정상 조회, 잘못된 프로젝트 URL, 삭제·누락 제보 검사가 통과한다.

## 6. 선택 사항: 실제 테스트 DB 통합 테스트

이 절차는 **비어 있거나 테스트 전용인 DB**에서만 수행한다. 운영 DB인지 확실하지 않다면 건너뛴다.

```powershell
$env:TEST_DATABASE_URL = "테스트용_PostgreSQL_연결문자열"
pnpm --filter @reproloop/web test -- report-detail.integration.test.ts
Remove-Item Env:TEST_DATABASE_URL
```

성공 기준:

- `1 passed`가 보인다.
- 첨부 metadata와 상태 이력이 조회된다.
- 상태 이력이 오래된 것부터 정렬된다.
- soft delete된 제보가 `null`로 처리된다.

`TEST_DATABASE_URL`을 설정하지 않았을 때 `skipped`가 보이는 것은 정상이다. 실수로 개발·운영 DB를 바꾸지 않도록 의도적으로 건너뛴 것이다.

## 7. 웹 서버 실행

프로젝트 루트에서 다음을 실행한다.

```powershell
pnpm --dir apps/web dev
```

다음과 비슷한 문구가 보일 때까지 기다린다.

```text
Local: http://localhost:3000
Ready
```

이 PowerShell 창은 서버이므로 닫지 않는다. 테스트를 마칠 때 `Ctrl+C`로 종료한다.

## 8. 화면에서 정상 흐름 확인

### 8-1. 로그인과 목록

1. Chrome에서 `http://localhost:3000/projects`를 연다.
2. 로그인 화면이 나오면 `Discord 로그인`을 누른다.
3. 팀의 테스트 프로젝트를 선택한다.
4. 제보 목록에 `BUG-번호`와 제목이 보이는지 확인한다.

목록이 비어 있으면 Discord 테스트 서버에서 `/bug`를 실행해 제보를 한 건 만든 뒤 브라우저를 새로고침한다. 자세한 제출 방법은 `B-3단계_Discord_bug_설정과_검증_가이드.md`를 따른다.

### 8-2. 목록에서 상세로 이동

1. 제보 행의 `BUG-번호`를 누른다.
2. 브라우저 주소가 다음 모양인지 확인한다.

```text
http://localhost:3000/projects/프로젝트UUID/reports/제보UUID
```

3. 브라우저 새로고침 버튼을 누른다.
4. 새로고침 뒤에도 같은 제보가 보이는지 확인한다.

성공 기준: 목록 클릭과 직접 새로고침이 모두 같은 상세 내용을 표시한다.

### 8-3. 상세 내용 확인

화면에서 아래 항목을 하나씩 찾는다.

- `BUG-번호`, 제목, 상태, 심각도
- 발생 빌드와 수정 빌드
- 제보자 표시 이름과 Discord ID
- 실제 결과, 예상 결과, 재현 단계, 발생 위치, 환경
- 플랫폼과 발생 빈도
- 첨부파일이 없으면 `첨부파일이 없습니다.` 안내
- `처리 이력`에 최초 접수 기록

Discord `/bug` modal에 썼던 실제 결과·예상 결과·재현 단계·플랫폼·빈도와 화면 내용이 같은지 비교한다.

## 9. 긴 글과 작은 화면 확인

1. 브라우저에서 `F12`를 눌러 개발자 도구를 연다.
2. 기기 모양 아이콘을 누른다.
3. 너비를 `390`, 높이를 `844` 정도로 맞춘다.
4. 제목, 재현 단계, 제보자 이름이 화면 밖으로 밀려 가로 스크롤을 만들지 확인한다.
5. 긴 문장이 줄바꿈되고 모든 내용이 읽히면 성공이다.

사용자 입력은 HTML로 해석되면 안 된다. 테스트 제보 제목이나 본문에 다음 문자열을 입력한 경우 화면에는 글자 그대로 보여야 한다.

```text
<b>굵게 되면 안 됨</b>
```

## 10. 오류 상태 확인

### 10-1. 잘못된 제보 주소

현재 주소의 마지막 제보 UUID를 다음 값으로 바꾸고 Enter를 누른다.

```text
00000000-0000-4000-8000-000000000000
```

성공 기준: `제보를 찾을 수 없습니다`가 표시되고 서버 내부 오류나 DB 정보가 화면에 나오지 않는다.

### 10-2. 다른 프로젝트를 주소에 넣기

정상 상세 주소에서 `projects/` 다음 프로젝트 UUID만 다른 프로젝트 UUID로 바꾼다.

성공 기준: 제보가 노출되지 않고 `제보를 찾을 수 없습니다`가 표시된다.

### 10-3. 로그아웃 상태

1. Discord 로그인 세션을 로그아웃하거나 시크릿 창을 연다.
2. 정상 상세 주소를 붙여넣는다.

성공 기준: `로그인이 필요합니다`와 `Discord 로그인` 버튼이 표시된다.

### 10-4. 조직 외 계정

1. 테스트 프로젝트의 조직 멤버가 아닌 Discord 계정으로 로그인한다.
2. 정상 상세 주소를 직접 연다.

성공 기준: `프로젝트 권한이 없습니다`가 표시되고 제목과 제보 원문은 보이지 않는다.

## 11. API를 직접 확인하는 쉬운 방법

로그인한 Chrome에서 정상 상세 화면을 연 상태로 `F12` → `Console`을 누르고 아래를 입력한다. `제보UUID`는 현재 주소 마지막 값으로 바꾼다.

```javascript
fetch("/api/v1/reports/제보UUID").then(async (r) => ({ status: r.status, body: await r.json() })).then(console.log)
```

성공 기준:

- `status: 200`
- `body.data.title`에 제목이 있음
- `body.data.statusEvents`가 배열임
- 최상위 응답이 `{ data: ... }` 모양임

없는 UUID로 같은 명령을 실행하면 `status: 404`와 `body.error.code: "NOT_FOUND"`가 나와야 한다.

## 13. 자주 만나는 문제

| 증상 | 확인할 것 |
|---|---|
| `DATABASE_URL is missing or empty` | `apps/web/.env.local` 파일명과 `DATABASE_URL` 철자 |
| Discord 로그인 후 다시 로그인 화면 | `AUTH_SECRET`, Discord callback URL, `APP_URL` |
| 프로젝트 목록이 비어 있음 | 로그인한 Discord 사용자가 DB의 조직 멤버인지 확인 |
| 제보 목록이 비어 있음 | 같은 프로젝트·활성 빌드로 `/bug`를 제출했는지 확인 |
| 상세가 404 | URL의 프로젝트 UUID와 제보 UUID 조합 확인 |
| 상세가 403 | 현재 계정의 조직 멤버 등록 확인 |
| 통합 테스트가 skipped | `TEST_DATABASE_URL` 미설정이면 정상 |
| 포트 3000 사용 중 | 기존 개발 서버를 `Ctrl+C`로 끈 뒤 다시 실행 |
